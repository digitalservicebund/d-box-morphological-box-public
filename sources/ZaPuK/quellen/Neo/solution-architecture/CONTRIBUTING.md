# Contributing

We are happy that you are looking into contributing to this project.

## How to Contribute

Please start by reading our [development workflow](docs/workflow.md) guidelines.
This architecture repository uses some additional contributing guidelines as
lined out in [docs/architecture.md](docs/architecture.md).

Once you are familiar with the development workflow, start your contribution
by opening a new **draft** Merge Request from your feature branch.

Once your feature is ready for review, move the Merge Request from
**draft** status and request a review from a project maintainer.

## Licensing

By contributing to this project, you are accepting the terms of the open
source licenses listed in our
[development workflow docs](docs/workflow.md#licensing). We encourage you
to add your personal copyright line when making non-trivial changes!

## In doubt? Ask

We are always happy to receive contributions, but we also like to discuss
technical approaches in order to solve a problem. This helps to ensure a
contribution fits the project strategy and roadmap, and potentially avoids
otherwise wasted time. So when in doubt please open an issue and start a
discussion, or join our public Matrix room at
[#neo:fitko.dev](https://matrix.to/#/#neo:fitko.dev?via=tchncs.de&via=nordeck.io&via=element.io).
